# ADR-001: 选择 ACP 协议作为人机交互标准

> 日期：2026-09-01
> 状态：已接受
> 决策者：OpenMate 开发团队

---

## 背景

OpenMate 需要一个标准化的协议来实现「人 ↔ Agent」的交互。市场上有多种 Agent 通信协议可选，需要确定一个作为核心交互标准。

## 考虑的方案

### 方案A：自定义 WebSocket 协议
- 描述：自己设计 JSON 消息格式，通过 WebSocket 通信
- 优点：完全可控，无外部依赖
- 缺点：无标准生态，第三方 Agent 无法直接接入，需要大量文档说明

### 方案B：Google A2A 协议
- 描述：Google 推出的 Agent-to-Agent 协议
- 优点：标准化，Google 背书
- 缺点：面向 Agent↔Agent 场景，不直接覆盖人↔Agent 交互

### 方案C：ACP（Agent Communication Protocol）
- 描述：开源 Agent 通信协议，JSON-RPC 2.0 over WebSocket
- 优点：标准化、轻量、已有 Python/JS SDK、支持流式输出、任务管理
- 缺点：生态尚在早期，部分功能需要扩展

## 最终选择

**选择方案C：ACP 协议**

## 理由

1. **三层协议隔离清晰**：ACP = 人↔Agent、A2A = Agent↔Agent、MCP = Agent↔工具，各司其职
2. **JSON-RPC 2.0**：成熟的标准，调试方便，工具链丰富
3. **流式输出支持**：ACP 原生支持 SSE 流式返回，适合 LLM 场景
4. **任务生命周期管理**：内置 task 创建/取消/状态查询，不需要自己实现
5. **开源社区活跃**：持续迭代中，有参考实现

## 风险 & 后续

- 风险：ACP 生态尚早期，可能需要自行扩展部分功能
- 缓解：保持自定义扩展点，通过 ACP Proxy 层隔离协议细节
- 后续：持续跟踪 ACP 协议更新，参与社区贡献
