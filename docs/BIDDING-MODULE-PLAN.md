## 二、核心模块设计

### 2.1 招标文件解析器 (parser.py)

**输入**：PDF/Word招标文件
**输出**：结构化JSON

```python
解析结果 = {
    "project_info": {
        "name": "项目名称",
        "budget": "预算金额",
        "deadline": "投标截止时间",
        "method": "综合评分法"
    },
    "scoring_criteria": {
        "technical": [{"item": "技术方案", "score": 30, "type": "主观"}],
        "commercial": [{"item": "企业业绩", "score": 20, "type": "客观"}],
        "price": {"formula": "最低价法", "weight": 30}
    },
    "qualification_requirements": [
        {"type": "★", "content": "营业执照", "mandatory": True}
    ],
    "technical_params": [
        {"product": "服务器", "param": "CPU", "value": "≥32核", "level": "★"}
    ],
    "废标条款": [...],
    "商务条款": [...],
    "格式模板": [...]
}
```

**技术方案**：
- PDF用pymupdf/pdfplumber提取文本+表格
- Word用python-docx读取
- LLM提取结构化信息（MiMo API）
- 与现有bidding-analysis skill共享解析逻辑

### 2.2 提纲生成器 (outline.py)

**输入**：解析结果JSON
**输出**：三级目录JSON

```python
提纲 = {
    "title": "技术方案",
    "children": [
        {
            "id": "1",
            "title": "需求理解与分析",
            "description": "对项目背景、业务需求、技术需求的全面理解",
            "children": [
                {"id": "1.1", "title": "项目背景理解", "description": "..."},
                {"id": "1.2", "title": "业务需求分析", "description": "..."}
            ]
        }
    ]
}
```

**策略**：
- 短标书（<50页）：一次性生成完整三级提纲
- 长标书（>50页）：分步生成（先一级→逐个二级三级）
- 提纲必须覆盖所有评分得分点
- 用户可手动编辑调整

### 2.3 正文生成器 (generator.py)

**核心设计**：逐章生成，上下文传递

```
项目概述 + 上级章节 + 同级章节摘要 → LLM → 当前章节正文
```

**关键特性**：
- 同级章节信息传给AI → 避免内容重复
- 配图预编排 → 正文为图片做铺垫
- 企业知识库注入 → 历史方案复用
- 超长文本支持 → 分章生成无字数上限

**配图策略**（借鉴易标）：
- 预编排阶段：为每个叶子节点分配配图类型（表格/Mermaid/AI生图）
- 正文生成后：独立执行配图，失败不影响正文

### 2.4 合规风控引擎 (compliance.py)

**这是超越易标的核心差异化！**

```python
规则引擎 = {
    "废标规则": [
        {"id": "F001", "desc": "★条款负偏离", "severity": "致命"},
        {"id": "F002", "desc": "报价超预算", "severity": "致命"},
        {"id": "F003", "desc": "未按格式填写", "severity": "致命"},
        {"id": "F004", "desc": "逾期递交", "severity": "致命"}
    ],
    "扣分规则": [
        {"id": "D001", "desc": "▲条款负偏离N项", "severity": "高"},
        {"id": "D002", "desc": "一般条款负偏离M项", "severity": "中"}
    ],
    "格式规则": [
        {"id": "G001", "desc": "封面信息完整性"},
        {"id": "G002", "desc": "签字盖章完整性"},
        {"id": "G003", "desc": "目录页码一致性"}
    ]
}
```

**300+规则覆盖**：
- 废标条款逐条检查
- 评分得分点覆盖验证
- 技术偏离表逐项校对
- 商务条款响应检查
- 格式规范检查
- 价格合规检查（三层约束）
- 查重检测（多标书交叉查重）

### 2.5 Word导出器 (exporter.py)

**技术方案**：直接操作docx zip内的XML

- 禁止使用python-docx写入（编号/样式有缺陷）
- 用LibreOffice UNO API / 直接修改XML
- 标题样式：H1黑体二号/H2宋体三号/H3宋体四号/正文仿宋小四
- 多级编号：技术方案用编号，资格材料不编号
- TOC域代码自动插入
- 分节符控制页码
- 横向页面自适应多列表格

### 2.6 企业知识库 (knowledge.py)

**与OpenSoul knowledge表集成**：

```
knowledge表存储：
- 历史投标方案（可复用的章节内容）
- 企业资质信息（自动填充资格材料）
- 项目业绩库（自动匹配评分要求）
- 技术方案库（按行业分类）
- 常用模板（封面/声明函/承诺函）
```

## 八、超越易标的差异化

| 维度 | 易标AI | OpenMate |
|------|--------|----------|
| 合规引擎 | 无独立规则引擎 | 300+规则，废标/扣分/格式全覆盖 |
| 知识库 | 简单的企业资料库 | 与OpenSoul知识大脑集成，自动沉淀 |
| 多Agent | 单一AI | 6-Agent协同（解析/生成/校核/竞争/报价/合规） |
| 部署方式 | SaaS+本地 | SaaS+私有化+断网+ACP协议标准化 |
| 安全 | 基础 | RBAC+审计日志+traceId全链路 |
| 协作 | 无 | ACP审批流+多人协同 |
| 行业深度 | 通用 | 教育/政务/军工垂直优化 |
