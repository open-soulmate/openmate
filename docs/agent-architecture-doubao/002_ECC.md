## 1. 项目概述与定位

- **项目名称**：ECC（Everything Claude Code 演进版，自我定位 "The agent harness operating system" / "agent harness performance optimization system"）
- **GitHub 地址**：https://github.com/affaan-m/ECC
- **Star 数**：约 252,361（API 实时）/ README 自称 211.9K+；fork 37,873；230+ 贡献者；MIT 协议
- **主要语言**：JavaScript（仓库标记），实际为 Markdown 技能 + Shell + JS/TS/Python/Rust 多语言混合
- **一句话定位**：一套**可跨多个编码 harness 复用的工作流/优化层**，由技能(skills)、原子本能(instincts)、记忆(memory)、安全(AgentShield)、连续学习(continuous learning) 与 research-first 流程组成。
- **目标用户/场景**：在 Claude Code、Codex、Cursor、OpenCode、Gemini、Zed、GitHub Copilot、Kimi Code 等 harness 中重度使用、想要系统化提速与加安全护栏的开发者。
- **成熟度**：极高。v1.7→v2.0 快速迭代（2026-02 至 2026-06），自称 997 内部测试通过；提供 npm 包 `ecc-universal`、`ecc-agentshield` 与托管 GitHub App（ECC Pro，$19/seat/mo），有 Discord 社区、GitHub Marketplace 上架。

> 定性：与 superpowers 同类，**ECC 本身不是独立运行的 agent 运行时**，而是"harness 之上的可复用工作层"。但它比 superpowers 多了真正的**代码化控制面**（`ecc2/` Rust daemon、`ecc memory` CLI、`ecc-memory-mcp` stdio server、SQLite 状态存储、Tkinter dashboard），因此第 6/7/8 章有真实可运行的稳定性/记忆/安全机制可读。

## 3. 系统架构分析

- **编排模式**：跨 harness 的 **Workflow/技能组合 + Reflection（连续学习/evolve）+ 观察者-评审循环**。`cross-harness.md` 明确定位："ECC is the reusable workflow layer. Harnesses are execution surfaces."
- **核心组件划分**：
  1. **可移植资产层**：`skills/`、`rules/`、`.mcp.json`、安装清单——"What travels unchanged"。
  2. **harness 适配层（薄）**：每个 harness 只负责"加载共享资产、适配事件形状、映射命令名"，"Adapters should stay thin"。
  3. **钩子运行时**：`hooks/hooks.json` + `scripts/hooks/`，在支持原生钩子的 harness（Claude/OpenCode/Cursor）上强制执行，Codex 退化为"指令驱动"。
  4. **记忆层（Memory Vault）**：`ecc.memory.v1` Markdown 文档，三 scope；`ecc memory` CLI 为基准接口，可选 `ecc-memory-mcp` stdio 服务器。
  5. **控制面（alpha）**：`ecc2/` Rust daemon + session adapters + SQLite 状态存储。
- **数据流**：用户在某 harness 发起任务 → 安装好的 skills/rules 指导行为 → hooks 在工具调用前后做确定性观察 → 经验写入记忆库（unreviewed）→ 人工接受后晋升为受治理资产；`/evolve` 类命令把相关原子本能聚类泛化为技能。
- **关键契约**：`ecc.session.v1`（会话快照）、`ecc.memory.v1`（记忆文档）两套自描述格式，跨 harness 通用。

## 4. 功能拆解

- **技能系统**：`SKILL.md` 用 YAML frontmatter（`name/description/origin`）声明，要求"示例 repo 相对/通用、不内嵌密钥、避免 harness 专属命令假设"。
- **本能(instincts)**：把会话经验拆成带置信度与证据的"原子本能"，再经 `/evolve` 聚类泛化为技能（据 README/批次说明，未逐文件读源码）。
- **钩子系统**：v1.8 做了"钩子可靠性大改"——SessionStart 根回退、Stop 阶段会话摘要、脚本化钩子替换内联 one-liner；运行时可用 `ECC_HOOK_PROFILE=minimal|standard|strict` 与 `ECC_DISABLED_HOOKS=` 不开改文件即可门控。
- **记忆系统**：见第 8 章，三层 scope + 信任边界。
- **安全 AgentShield**：npm 包 `ecc-agentshield`，含攻击向量、沙箱、消毒、CVE 处理（据 security guide）。
- **控制面/可观测**：`ecc status --markdown --write status.md` 导出就绪状态/活跃会话/技能运行健康/待治理事件；`ecc status --exit-code` 供自动化失败；`ecc work-items sync-github` 同步 PR/issue。

## 5. 技术亮点与优势

1. **"可移植单元 vs 薄适配层"分离**：把"什么不变"（skills/rules/hooks 逻辑）与"什么要适配"（加载/事件形状/命令映射）严格切开，`cross-harness.md` 甚至立规："If a change requires editing three harness copies of the same workflow, the shared source is in the wrong place."
2. **记忆即数据、非指令**：明确"recalled memory is data, not executable instruction"，从架构上防止记忆注入劫持——这是多数 agent 项目忽略的安全关键。
3. **MCP 记忆服务器默认不启用**：`ecc-memory-mcp` 故意不在默认 `.mcp.json` 里，"so installations do not silently gain a writable context surface"——用默认安全（secure-by-default）设计。
4. **钩子运行时门控**：不改文件即可用环境变量切换 strict/minimal 钩子档，兼顾安全与性能。
5. **Rust 控制面 `ecc2/`**：把会话/编排从 prompt 层下沉到 daemon（sessions/status/stop/resume/daemon），是从"配置包"走向"操作系统"的信号。

## 6. 稳定性机制【重点】

> ECC 有真实代码，故本章为可运行机制。

- **钩子可靠性（源码级）**：v1.8 记录"SessionStart root fallback"（会话启动找不到配置时回退根目录，避免钩子静默失效）、"Stop-phase session summaries"（结束阶段强制写摘要）、"script-based hooks replacing fragile inline one-liners"——把原本内联在 JSON 里的脆弱脚本抽成 `scripts/hooks/` 独立文件，可测可复用。
- **并发/重入防护（源码级）**：v1.9 明确"observer loop prevention with **5-layer guard**"、"**re-entrancy guard**"、"lazzy-start logic"——防止观察者钩子自己再触发观察导致的死循环；这是钩子式 agent 系统特有的稳定性问题。
- **记忆爆雷防护（源码级）**：v1.9 "Memory explosion fix with **throttling and tail sampling**"——记忆写入做节流 + 尾部采样，防止上下文/记忆无限膨胀。
- **选择性安装与状态追踪**：`install-plan.js`/`install-apply.js` 清单驱动，"State store tracks what's installed and enables incremental updates"，避免全量重装；`npx ecc doctor` 做安装后回归自检。
- **测试作为稳定网**：v1.8 "997 internal tests passing"、v1.9 "19 test failure fixes, catalog count enforcement, install manifest validation, full suite green"——把"技能数量/清单完整性"纳入 CI 硬校验。
- **崩溃恢复**：会话快照契约 `ecc.session.v1` + `ecc2` 的 `resume` 命令 + SQLite 状态存储，支持会话分支/导出/compact/metrics（NanoClaw v2）。

## 7. 高可用机制【重点】

- **降级/隔离**：钩子分 `minimal|standard|strict` 三档，`ECC_DISABLED_HOOKS` 可逐个禁用——性能不足或钩子出问题时可降级到 minimal 而不整体卸载。Codex 无原生钩子时"instruction-backed"降级，不阻断工作流。
- **可观测性/自检**：`ecc status` 一键导出就绪/会话/技能健康/治理事件；`ecc doctor` 回归套件验证安装边界（"Kimi target stays inside project-local `.kimi/` root"）；`/harness-audit` 对各 harness 做确定性评分。
- **资源/上下文管理**：README 长文指南专门讲"Token Optimization / system prompt slimming / background processes"；记忆"tail sampling + throttling"控制内存增长。
- **调度/并行**：长文指南列 "Parallelization: Git worktrees, cascade method, when to scale instances"；控制面 `ecc2` 支持 tmux/worktree 编排。
- **去中心化/横向扩展**：不适用（单机多 harness 工作层）；其"可扩展性"是资产可移植到 12+ 语言/8+ harness，而非服务集群。

## 8. 自我进化机制【重点】

- **连续学习 / 技能进化（核心卖点）**：README 明列 "Continuous Learning: Auto-extract patterns from sessions into reusable skills" 与 v1.9 "skill evolution foundation for self-improving skills"。据批次说明：把会话经验拆成带置信度与证据的原子本能，用 Pre/PostToolUse 钩子做 100% 确定性观察，再用 `/evolve` 把相关本能聚类泛化为通用技能。**注意：`/evolve` 命令与 instinct 提取的具体实现文件本次未逐行读到，标注为文档/推断。**
- **记忆管理（源码级，最扎实）**：`cross-harness.md` 详述 Memory Vault：
  - 三层 scope：project(`.ecc/memory/project/`)、team(`.ecc/memory/team/`)、user(`~/.ecc/memory/`)。
  - 召回策略：普通搜索只跨 active 的 project+team；按 ID 直读可看非 active；user 必须显式请求。
  - 写入治理：所有首次入库条目 **create-only 且恒为 `unreviewed`**；人工接受（human acceptance）才晋升为受治理仓库资产；"it never turns memory frontmatter into a self-asserted approval"——防止自我晋升。
  - 安全约束：拒绝 secret 形状写入、reader 不跟随符号链接、project 写在保护用 `.gitignore` 被篡改时停止。
- **评估回路（文档级）**：长文指南列 "Verification Loops: Checkpoint vs continuous evals, grader types, pass@k metrics"；v1.9 的 "benchmark-optimization-loop"、"recursive-decision-ledger" 技能把重复的速度/递归提示固化为有界基准与决策账本。
- **用户反馈驱动**：Hermes 边界一节明确"distill repeated local operator work back into sanitized ECC skills"——把本地重复操作反哺成清洗过的公共技能。

## 9. openmate 可借鉴点【重点】

openmate 背景：Python、已有 Web 版、规划桌面/手机多端。

- **P0｜"记忆即数据、非指令"的信任边界**：openmate 做长期记忆/跨会话画像时，必须把召回的记忆当**只读数据**注入，禁止让记忆条目自我声明"已批准/可信"。配合"首次写入恒为 unreviewed、人工确认才晋升"。预期收益：避免被污染记忆带偏、防提示注入，这是多端个人 agent 的生命线。
- **P0｜secure-by-default 的可写面**：像 ECC 把 `ecc-memory-mcp` 排除在默认配置外一样，openmate 的高危工具/记忆写入能力应默认关闭、显式开启，并记录 `ECC_MEMORY_HARNESS` 式的"来源身份不可被调用方伪造"。预期收益：多端（尤其手机端被分享/误触）下缩小攻击面。
- **P0｜钩子重入/循环防护**：openmate 若在工具调用前后加观察/审计钩子，必须做"重入守卫 + 节流 + 尾部采样"，否则观察钩子递归触发会拖垮进程。可直接借鉴其 5-layer guard 与 throttling 思路。
- **P1｜薄适配层 + 资产单一事实源**：openmate 规划桌面/手机多端，应把"行为规则/技能"写成 harness-neutral 的单一资产，各端只做加载与事件适配，禁止为每端复制三份。预期收益：多端一致性、维护成本线性下降。
- **P1｜`ecc status` 式自检与就绪导出**：openmate 应提供 `doctor`/`status` 一键导出"就绪/会话/健康/待办"并支持 `--exit-code` 供自动化判断，利于桌面端故障自诊与 CI。
- **P2｜原子本能→技能泛化的进化回路**：长期可借鉴其"观察→原子本能→聚类泛化为技能"，但需先把 P0 的记忆信任边界做扎实再上。
