## 3. 系统架构分析

### 编排模式：教材体系（非产品架构）——文档确认

全书核心公式 **Agent = LLM + 上下文 + 工具**（README:10/63）。10 章层层递进：

| 章 | 主题 | 核心 |
|---|---|---|
| 1 | 入门 | Agent = LLM+上下文+工具；**Harness 工程才是竞争力** |
| 2 | 上下文工程 | KV Cache、提示工程、**Agent Skills**、上下文压缩 |
| 3 | 用户记忆与知识库 | 用户记忆、RAG、结构化索引、知识图谱 |
| 4 | 工具 | **MCP 协议**、感知/执行/协作三类工具、主动工具发现 |
| 5 | Coding Agent 与通用 Agent | 代码是"能创造新工具的工具" |
| 6 | 交互（观察/动作空间扩展） | 异步事件驱动、语音、Computer Use、机器人 |
| 7 | 评估 | 评估环境、指标、统计显著性、评估驱动选型 |
| 8 | 模型后训练 | 预训练/SFT/RL 三阶段、工具调用内化 |
| 9 | **Agent 持续进化** | 从运行轨迹获学习信号，更新知识/指令/程序/参数 |
| 10 | **多 Agent 协作** | 协作框架、上下文共享/隔离、涌现的"Agent 社会" |

v2.0 把"异步交互"与"多模态"合并为第 6 章，原 6/7/8 章后移为 7/8/9（README:16）。

## 5. 技术亮点与优势

1. **"Harness 工程才是竞争力"**：与"调 API 就是 agent"的流行叙事相反，本书把系统工程（上下文/工具/记忆/评估/进化）立为主线，与本批源码调研结论一致。
2. **公式化提纲挈领**：Agent = LLM + 上下文 + 工具，后续章节全是这三者的展开。
3. **实验与正文闭环**：109 个可跑实验，不是纯讲理论。
4. **覆盖进化与多 agent**：第 9 章"持续进化"、第 10 章"多 agent 协作"正对本批重点章。

## 6. 稳定性机制【重点】

**不适用（说明原因）**：教材项目，无生产服务。其"工程严谨性"体现在：实验环境用 `uv.lock` 锁定可复现、实验状态单独记录（clone 源码≠实验完成，README:128）、按章隔离依赖、凭据用 `.env` 不入库。这些是"教学工程稳定性"，非运行时稳定性。

## 8. 自我进化机制【重点】

这是本书第 9 章的主题（"Agent 的持续进化"，9 个实验），讲"从运行轨迹获得学习信号，更新知识、指令、程序与参数"。它是**方法论教材**，不是已实现的进化系统。对 openmate 的借鉴在于它把"进化"拆成四层：更新知识（记忆/RAG）、更新指令（prompt/skill）、更新程序（工具/代码）、更新参数（SFT/RL）——这恰好对应本批 nanobot（记忆/Dream）、CowAgent（自进化）、humanizer（skill）的实证。

---

## 9. openmate 可借鉴点【重点】

openmate 背景：Python AI Agent 应用，已有 Web 版，规划桌面/手机多端。

- **【P0】把 Agent 收敛为"LLM + 上下文 + 工具"三要素来审计**：openmate 设计每个功能时，问自己——改的是上下文（prompt/记忆）、工具（MCP/skill）还是模型？本书第 1 章的 Harness 视角提醒：竞争力在工程不在模型本身。
- **【P0】按"进化四层"规划 openmate 的自我改进**：知识层（记忆/RAG）→ 指令层（skill/prompt）→ 程序层（工具/代码）→ 参数层（暂不需要）。openmate 先做前两层最划算。
- **【P1】上下文工程是能力上限**：第 2 章强调上下文压缩、Agent Skills、KV Cache，openmate 多端都要省 token，应优先投资上下文管理。
- **【P1】用可复现实验/评估驱动**：第 7 章讲评估驱动选型，openmate 改 prompt/工具后应有最小回归集，别靠感觉。
