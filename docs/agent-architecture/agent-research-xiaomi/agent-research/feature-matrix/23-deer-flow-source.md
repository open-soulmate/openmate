## 源码亮点

1. **单图 + 中间件链代替多图编排**：所有能力（记忆、摘要、todo、标题生成、循环检测、HITL、token 统计、子代理限额）都是 langchain-agents middleware，挂在 `wrap_model_call`/`after_model`/`after_agent` 生命周期钩子上，lead_agent/agent.py 只做装配。加功能=加中间件，不改图拓扑。
2. **身份双键设计**（subagent）：provider tool_call_id 只做消息关联，服务端 execution_id 做所有权/超时/取消——注释明确"provider ID 跨父 run 不唯一，绝不能当注册表所有权键"。这类"踩过坑后的不变量"全仓库以模块 docstring 形式沉淀（AGENTS.md + 每个子目录 AGENTS.md），本身就是极好的架构文档样本。
3. **危险注入点的延迟策略**：loop 警告延迟到下一次 wrap_model_call 才注入，因为 after_model 时刻 tool_call/tool_message 尚未配对，OpenAI/Anthropic 校验会拒绝请求——对 LLM provider 约束的精确理解。
4. **fail-open 防护写进数据结构**：AllowlistProvider 用 `None vs []` 区分"未配置=全放行"与"显式空=全禁"，避免 truthiness 塌缩导致 fail-open。
5. **非交互运行显式剔除 ask_clarification**：定时任务把 HITL 工具从工具集移除而非靠 prompt 约定，`disable_clarification`、`non_interactive` 等 server 私有键对客户端输入双通道清除。
6. **CI 级技能安全治理**：公共技能改动必须过 skill-reviewer，waiver 条目绑定 SHA-256 + 过期日 + 需两次合并生效（先落 manifest 再消费 hash），blocker 永不可豁免。
7. **harness/app 严格分层**：`deerflow` 永不 import `app`，由 `tests/test_harness_boundary.py` 在 CI 强制；框架可独立发布（deerflow-harness 包）。

## 可复用设计

对 OpenMate（前端）+ OpenSoul（后端）按优先级：

1. **P0 三件套（长时程可靠性最小集）**：① loop 检测哈希滑窗（OpenSoul，1 个中间件）；② ask_clarification + interrupt/resume 协议（OpenSoul 工具 + OpenMate 表单卡片，需定义 versioned `human_input_response` 元数据契约）；③ 定时任务 queued/launching/running 状态机 + 单活跃唯一约束（扩展 hermes_cron）。
2. **P0 子代理执行引擎**：照抄 OpenSoul 缺失的后台执行注册表——execution_id/tool_call_id 双键、容量信号量、超时取消清理；委派时注入报告契约 + 验收标准两个 system prompt 模板（成本几乎为零，质量提升明显）。
3. **P0 token 预算三层**：会话级 token_budget + 工具输出 budget + 超预算 synopsis，是 goal loop / 长任务的前置条件。
4. **P1 延迟目录统一**：tool_search 与 describe_skill 共用一个 DeferredToolCatalog（名字进 prompt、schema 按需拉取、promotion 记 thread 状态），OpenSoul MCP 工具和技能库增长后收益最大。
5. **P1 不可信数据渲染约定**：durable context 的"权威规则=SystemMessage、不可信数据=隐藏 HumanMessage、永不回写状态"三分法，直接作为 OpenSoul prompt 组装规范。
6. **P2 文档实践**：每个子目录一个 AGENTS.md 沉淀不变量与踩坑记录 + CI 测试锁定边界（如 test_harness_boundary.py），OpenSoul 目录命名（器官隐喻）可配套同级"器官 AGENTS.md"。
