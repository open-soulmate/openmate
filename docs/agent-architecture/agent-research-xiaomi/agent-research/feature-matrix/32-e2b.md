# E2B (#81, 8k★) 功能研究

研究时间：2026-09-16 cron第27轮（第二阶段深研）
源码：github.com/e2b-dev/e2b（shallow clone，2026-09快照）
结构：SDK monorepo——packages/{js-sdk, python-sdk, code-interpreter-js/python, desktop-js/python, cli} + spec/(envd协议OpenAPI) + templates/

**重要背景**：本仓库只含SDK/CLI/解释器/桌面包，**Firecracker微VM编排器是e2b云服务**（自托管需另外的infra仓库/企业版）。SDK通过envd协议（gRPC+HTTP，spec/有完整OpenAPI）控制沙箱。对标自建时价值在**API设计**而非代码复用。

## 源码亮点

1. **envd协议**：SDK与沙箱间用单一定义良好的协议（spec/openapi.yml完整可读），SDK多语言只是协议的皮。自建沙箱时先定协议再写实现，JS/Python SDK半天可双出。
2. **fork语义**：agent架构级创新点——一个沙箱跑出岔路时fork副本继续，主线不受污染。对应LLM的"beam search式执行"。
3. **图表结构化提取**：把"执行结果"从文本/图片升级为**结构化数据**（Chart{type, scale, series}），前端可重建可交互。这是code interpreter类产品被忽视的杀手细节。
4. **git凭证注入**：clone时动态带凭证、失败重试、不落盘。agent操作私有仓库的标准做法。
5. **资源自动回收**：set_timeout是每个sandbox的默认行为——防agent开了沙箱忘了关。

## 结论

e2b真正的护城河（Firecracker编排、亚秒级启动、多租户调度）是云基础设施，**自建不需要也不现实**。但它的SDK API面是**沙箱执行器的参考设计标准**：生命周期/fork/snapshot/volume/secret/网络控制/指标，OpenSoul自建Docker沙箱时照这个面设计，未来想换e2b云或其它后端只换driver。两个不依赖沙箱、立即可抄的高价值点：**图表结构化提取**和**watch_dir事件触发**。
