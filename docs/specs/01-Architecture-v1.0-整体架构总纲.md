# 1\. 整体五层架构分层模型（全局永久固化）

OpenSoulMate 整体架构分为 **五层固化分层**，自上而下逐级依赖、单向收敛，层级永久固定，禁止乱层、跨层、反向依赖。

## 1\.1 第一层：应用接入层（最上层）

面向用户、前端、租户、外部系统的统一入口。

- 前端控制台、租户后台、运维控制台

- 外部 API 接入、第三方系统对接

- 人机交互入口、任务发起入口

**职责**：请求接入、鉴权前置、路由分发、流量接收

## 1\.2 第二层：智能体业务层（核心业务域）

整个系统的**业务能力核心**，所有智能体能力、任务、知识库、记忆全部收敛于此。

- AgentCore 智能体内核

- Memory 记忆系统

- Artifact 知识库产物系统

- TaskScheduler 任务调度系统

- PromptStore 全局提示词资产系统

**职责**：业务逻辑、智能体推理、任务编排、记忆管理、知识管理、Prompt 管理

## 1\.3 第三层：统一网关与通信层（能力中转层）

所有底层调用、模型调用、跨服务通信的**统一收口层**。

- Gateway 集群网关

- ModelGateway 模型统一网关

- 三层通信协议体系：ACP / A2A / MCP

**职责**：流量路由、模型代理、跨节点通信、协议标准化、负载均衡、限流熔断

## 1\.4 第四层：中间件与扩展层（解耦扩展层）

支撑上层业务的**解耦底座与扩展能力**。

- EventBus 分布式事件总线（全局解耦核心）

- Plugin 插件扩展系统（所有自定义能力收口）

- Config 配置中心

- RBAC 权限体系

**职责**：系统解耦、动态扩展、配置管控、权限治理、事件驱动

## 1\.5 第五层：底座可观测与运维层（最底层）

整个集群的**稳定保障、观测、治理、容灾底层底座**。

- Telemetry 遥测全观测体系（Trace/Log/Metric/Event）

- Monitor 指标监控大盘

- Alert 告警中心

- SLA 服务等级保障体系

- Health 健康检查体系

- Backup 集群备份恢复体系

- Log\&Trace 链路日志体系

- ErrorCode 全局错误码体系

**职责**：稳定性保障、故障发现、性能观测、SLA 考核、容灾备份、全链路审计

# 2\. 全局核心通信范式（架构固化）

## 2\.1 三层通信协议体系（固定不变）

- **ACP（人机协议）**：用户 \<\-\> 集群交互

- **A2A（Agent对等协议）**：Agent \<\-\> Agent 协同交互

- **MCP（底层管控协议）**：运维、管控、节点、服务底层交互

## 2\.2 双驱动运行模型

- **RPC 即时调用**：实时请求、模型调用、接口查询

- **EventBus 事件异步驱动**：状态变更、生命周期、异步解耦

# 3\. 全局架构治理体系

## 3\.1 统一可观测治理（唯一数据源）

所有监控、日志、链路、指标、SLA、故障统计**全部源自 Telemetry**，全局唯一可信数据源，杜绝多口径混乱。

## 3\.2 统一权限治理

全集群所有能力、接口、数据、配置统一由 RBAC 管控，租户隔离、角色隔离、操作隔离。

## 3\.3 统一扩展治理

所有自定义业务扩展、能力增强、逻辑拦截**统一走 Plugin 插件体系**，禁止硬编码侵入内核。

## 3\.4 统一容灾治理

健康检查、故障熔断、自动降级、备份恢复、SLA 考核，全方位保障集群高可用。

# 4\. 全局架构强制约束（架构红线，不可突破）

1. **层级单向依赖**：上层依赖下层，下层绝不反向依赖上层

2. **内核零侵入**：所有扩展能力必须插件化，禁止修改内核主流程

3. **模型调用唯一入口**：所有模型调用必须经过 ModelGateway

4. **提示词唯一托管**：所有 Prompt 必须托管 PromptStore，禁止硬编码

5. **状态变更唯一出口**：所有状态变更必须通过 EventBus 事件广播

6. **观测数据唯一源头**：所有可观测数据必须通过 Telemetry 采集上报

7. **通信协议统一标准**：所有交互必须遵循 ACP/A2A/MCP 三层协议

8. **多租户强隔离**：数据、资源、流量、配置、观测全程租户隔离
