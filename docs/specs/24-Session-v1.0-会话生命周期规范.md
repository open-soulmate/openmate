**OpenSoulMate Session v1.0 会话生命周期规范（定稿冻结）**

**0. 规范总览**

**0.1 定位**

本规范定义 OpenSoulMate **会话模型、会话创建、状态流转、冻结、恢复、销毁、会话上下文管理、会话隔离、会话快照、会话元数据**。

会话是整个 OpenSoulMate 系统交互最小执行载体，所有 Agent 任务、工具调用、权限校验、资源归属全部绑定 session\_id。

**0.2 解决核心问题**

* 会话状态混乱，断线后无法恢复上下文
* 会话资源不会自动回收，内存 / 磁盘持续泄漏
* 会话状态缺乏标准流转定义，各模块对会话生命周期理解不一致
* 会话冻结、超时策略不统一，长任务意外中断
* 多 Agent 子会话、嵌套会话管理无标准，资源归属混乱

1. 标准化会话有限状态机，全模块统一状态定义
2. 会话快照持久化，支持断线恢复、冷启动恢复
3. 会话资源自动绑定与自动回收（内存缓存、L2 临时目录、子任务、子 Agent）
4. 支持主会话 + A2A 嵌套子会话模型

**1. 核心概念定义**

1. **session\_id**：全局唯一会话标识，UUID 格式，全局不可重复
2. **主会话 (Main Session)**：用户直接发起的顶层会话，归属 user\_id
3. **子会话 (Child Session)**：A2A 委派子 Agent 自动创建，依附主会话，生命周期跟随主会话
4. **会话状态机**：控制会话全生命周期流转
5. **会话上下文 Context**：会话内全局状态、对话历史、任务队列、工具执行记录
6. **会话快照 Snapshot**：将当前会话完整状态落地至 L3 持久化存储，用于断电 / 断线恢复

**2. 会话状态枚举（强制固定）**

|  |  |
| --- | --- |
| 状态 | 说明 |
| init | 初始化，会话创建中，资源预分配，未就绪 |
| active | 活跃状态：可接收用户消息、可执行 Agent 任务、可调用工具 |
| frozen | 冻结状态：暂停新任务，内存 L1 缓存降级落地快照，保留持久化数据，不接收新任务 |
| resuming | 恢复中：从 L3 快照加载上下文，状态回迁活跃 |
| destroy\_pending | 待销毁：标记准备清理，拒绝新请求，等待子任务收尾 |
| destroyed | 已销毁：L1/L2 资源彻底回收，L3 归档保留，不可恢复 |

**3. 会话创建规范**

**3.1 主会话创建流程**

1. 用户鉴权通过，网关发起会话创建请求
2. 生成全局唯一 session\_id，绑定 user\_id、角色权限快照
3. 在 Storage 初始化标准目录结构：/data/temp/{session\_id}
4. 写入会话元数据至 L3 持久化目录
5. 初始化空状态树、空任务队列，生成首个基础快照
6. 会话状态置为 active，下发会话 Token
7. 写入审计日志，绑定全局 trace\_root\_id

**3.2 子会话创建规则（A2A）**

1. 子会话由主会话 Agent 委派子任务时自动创建
2. 子会话默认继承主会话**最小权限子集**，禁止超权继承
3. 子会话必须携带 parent\_session\_id，建立顶层归属链路
4. 主会话销毁，所有嵌套子会话强制进入销毁流程
5. 子会话拥有独立快照，但审计、日志、追踪统一归属主会话链路

**4. 会话快照 & 断线恢复规范**

**4.1 快照强制触发时机**

1. 会话状态由 active → frozen，强制全量快照落地
2. 长任务执行过程中，定时增量快照
3. 重大 State 变更、关键 Artifact 产出后立即快照
4. MCP 手动快照触发接口

**4.2 快照标准包含内容**

* 会话完整元数据、归属关系、时间线
* 全局 Σ State 状态树
* 对话历史、任务队列、未完成工具调用上下文
* 当前用户权限快照、标签、运行配置
* 当前会话所有 Artifact 索引清单

**4.3 断线 / 重启恢复流程**

1. 用户传入合法 session\_id，校验归属与权限
2. 读取 L3 最新完整快照
3. 加载状态树、任务队列、上下文至 L1 内存
4. 状态切换为 resuming，完成回迁后置为 active
5. 断点续跑未完成任务，接续正常交互

**5. 会话冻结规范**

**5.1 冻结触发条件**

1. 空闲超时无交互（系统全局 TTL 控制）
2. 用户手动暂停会话
3. 系统内存水位过高，自动冻结低优先级空闲会话
4. 安全风控命中规则，临时冻结会话

**5.2 冻结行为约束**

1. 停止接收新任务、新工具调用
2. 可配置：运行中任务「暂停」或「跑完收尾」
3. 强制落地一次全量快照至 L3
4. L2 临时目录保留、不清理
5. 会话 Token 保持有效，支持随时恢复

**6. 会话销毁与资源 GC 规范**

**6.1 销毁触发条件**

1. 用户主动关闭会话
2. 冻结超最大保留期限，系统自动回收
3. 账号注销、用户资源回收
4. 安全风控判定恶意会话，强制销毁

**6.2 标准化销毁执行顺序（强制不可逆）**

1. 状态变更为 destroy\_pending，拦截所有新请求
2. 终止所有运行中子任务、子 Agent、子会话
3. 清空 L1 内存会话缓存、运行上下文
4. 递归删除 L2 /temp/{session\_id} 全部临时资源
5. 吊销当前会话所有 Token
6. 标记状态为 destroyed
7. **保留 L3 持久化：元数据、快照、日志、Artifact、审计记录**（用于合规复盘）

**8. 会话隔离红线规范**

1. 不同会话内存上下文**完全隔离**，禁止跨 Session 读取对话、状态、变量
2. L2 临时目录强隔离，禁止跨会话读写、遍历、篡改
3. 子会话仅可读取主会话授权产物，**禁止反向修改主会话资源**
4. 所有资源归属 session\_id，归属关系不可篡改、不可转移
5. 销毁会话绝不影响其他活跃会话数据安全

**9. MCP 全局管控能力**

1. 全量会话列表、按用户 / 状态 / 时间筛选
2. 手动冻结、恢复、强制销毁会话
3. 手动触发快照、导出会话备份
4. 全局会话统计：活跃、冻结、待销毁、今日新增
5. 批量过期会话自动 GC 调度

**10. 系统红线禁止规则**

1. ❌ 禁止无 Session 裸执行业务、工具、任务
2. ❌ 禁止跨会话读取内存上下文、越权访问资源
3. ❌ 禁止销毁态会话复用、二次恢复
4. ❌ 禁止销毁会话时删除审计归档类持久化数据
5. ❌ 禁止子会话权限、资源优先级超越父会话
