# OpenSoulmate 全局时间规范（统一标准文档）

## 1\. 规范目的

统一 Web / Tauri 客户端、Node\.js 服务端、日志、协议、数据库、渲染展示的所有时间行为，解决：

- 前后端时间精度不一致（ms/μs/ns 混用）

- 日志排序、链路追踪时间错位

- 消息创建时间、更新时间、响应时间混乱

- 本地时间 / UTC 混用导致时区 bug

- Trace 链路计时精度不足问题

本规范为 **OpenSoulmate 强制全局标准**，所有新代码必须遵守。

## 2\. 核心原则（三条铁律）

**1\. 存储、传输、日志一律使用 UTC 时间**

**2\. 底层高精度计时用纳秒，业务时间戳用毫秒**

**3\. 所有展示层统一本地时区，底层永远 UTC**

## 3\. 各环境精度能力定义（官方固定）

### 3\.1 浏览器 / Tauri 前端

- `Date.now()` → **毫秒\(ms\)** 标准业务时间戳

- `performance.now()` → **微秒级\(μs\)** 用于耗时计算

- 前端 **无法获取纳秒**（浏览器安全粒度限制）

### 3\.2 Node\.js 服务端

- `Date.now()` → 毫秒业务时间

- `process.hrtime.bigint()` → **真实纳秒\(ns\)** 高精度计时、链路耗时、日志

### 3\.3 Tauri Rust 层（可选）

支持系统纳秒时间，可作为最高精度计时来源。

## 4\. 全局统一时间分层标准（最重要）

OpenSoulmate 所有时间分为两层：**业务时间** 和 **链路高精度时间**

### 4\.1 业务层时间（所有数据库、消息、实体、接口）

**单位：毫秒 ms**

**格式：UTC 时间戳（number）**

**获取方式：Date\.now\(\)**

适用场景：

- 消息创建时间、更新时间

- 会话创建时间

- 用户行为记录

- 数据库所有时间字段

- HTTP 接口传参、返回值

原因：毫秒足够业务使用、无溢出、兼容所有设备、无时区问题。

### 4\.2 链路/性能高精度时间（日志、Trace、耗时统计）

**前端：微秒 μs**

**服务端：纳秒 ns**

适用场景：

- AI 推理耗时

- 消息往返耗时

- 函数执行耗时

- TraceId 链路计时

- 日志精细排序

## 5\. 字段命名统一规范（全局强制）

|字段名|精度|用途|环境|
|---|---|---|---|
|createTime|ms|实体创建时间|全端统一|
|updateTime|ms|实体更新时间|全端统一|
|costMs|ms|业务耗时（展示用）|全端统一|
|costUs|μs|前端精细耗时|前端|
|costNs|ns|后端高精度耗时、日志|Node 服务端|

## 6\. 时区强制规范

### 6\.1 底层存储/传输/日志

**一律 UTC，禁止本地时间戳**

禁止使用：`new Date().toString()`、本地时间字符串

必须使用：时间戳数字

### 6\.2 页面展示层

**一律转为用户本地时区展示**

聊天消息时间、日志面板、统计时间，全部本地时间显示。

## 7\. 前后端时间工具函数标准（可直接落地）

### 7\.1 前端通用时间工具（JS/TS）

```typescript
// 业务标准时间戳（全局唯一业务时间源）
export const getTimestamp = () => Date.now();

// 前端高精度耗时（微秒）
export const getHRTime = () => performance.now() * 1000; // 统一转微秒
```

### 7\.2 后端 Node 通用时间工具

```typescript
// 业务毫秒时间戳
export const getTimestamp = () => Date.now();

// 高精度纳秒时间戳
export const getNsTime = () => process.hrtime.bigint();

// 计算耗时（纳秒转毫秒，保留小数）
export function calcCostMs(startNs: bigint) {
  const diffNs = getNsTime() - startNs;
  return Number(diffNs) / 1000000;
}
```

## 8\. 消息会话系统专属规范（解决你之前的问题）

针对聊天输入框、多轮会话、自动 Prompt 扩展场景：

### 8\.1 会话生命周期时间规则

- **会话首次用户消息 = 初始化 Prompt 扩展时机**

- 后续轮次 **禁止自动生成 Prompt 扩展**（彻底解决重复叠加）

- Prompt 扩展属于「会话初始化行为」不属于「每轮发送行为」

### 8\.2 判定标准（全局统一）

```typescript
// 本轮是否为会话首轮
export function isFirstSessionTurn(messages: {role:string}[]) {
  return messages.filter(m => m.role === 'user').length === 0;
}
```

## 9\. 日志打印规范

- 前端日志：记录 `timeMs`、`costUs`

- 后端日志：记录 `timeMs`、`costNs`

- 所有链路日志必须带统一时间戳，保证前后端日志可串联排序

## 10\. 禁止行为（红线）

- 禁止使用本地时间字符串存库

- 禁止前端自行拼接年月日作为唯一时间ID

- 禁止业务层使用纳秒（过大、冗余、JSON 麻烦）

- 禁止高精度计时混用 Date\.now\(\)

- 禁止多轮会话重复自动生成 Prompt 扩展

## 11\. 总结一句话版本（全员熟记）

**业务毫秒 UTC 存，前端微秒后端纳秒算，展示本地、底层 UTC，首轮初始化、多轮不重写。**
